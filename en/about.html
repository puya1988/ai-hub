About AI HUB

A pure-static, dependency-free, freely modifiable AI information hub.

What this is

AI HUB regroups information that is normally scattered across news sites, paper archives, model leaderboards and tool directories, and reorganises it around what people actually want to know. It is not a newsroom — it is an index and navigation layer that helps you find what to read, what to use and what to learn.

Sections
  • News hub across 9 subject areas
  • Model library with 24 profiles and a comparison table
  • Tool directory with 48 tools by use case
  • Landmark papers plus conference information
  • Six-stage learning path with resources
  • Glossary of 82 core terms
  • Timeline of seven decades of AI
Engineering
  • Static: HTML + CSS + vanilla JS, no build step
  • Zero dependencies: no libraries, no CDNs
  • Auto-updating: RSS fetched by a script, no backend
  • Responsive across desktop, tablet and mobile
  • Dark mode × 6 accent themes, freely combined
  • Site-wide search with ⌘K / Ctrl+K
  • Model comparison, up to 4 side by side
  • Bilingual: Chinese and English datasets
  • Scheduled deployment: daily fetch plus auto-publish via GitHub Actions
  • Open index.html directly — no server needed

Data sources and how to update them

Curated content lives in one file per language — assets/js/data.zh.js and assets/js/data.en.js. Interface strings live in assets/js/i18n.js. Rendering logic never contains content, so updating text requires no HTML or CSS changes.

1
Manual

Edit the arrays in the language data file, keeping the field names. Best for a personal site.

2
Scheduled fetch (built in)

Run python3 scripts/fetch_news.py to pull the configured feeds; schedule it with cron.

3
Live API

Switch to fetching a remote JSON endpoint for genuinely real-time updates; requires a server.

Field reference and integration examples: assets/js/README-数据接入.md (Chinese) and README.md.

Changelog

Added a bilingual hardware recommendation module organised along two axes.
1. By environment: commercial versus industrial grade across 16 attributes — operating temperature, supply longevity, ECC, shock, EMC, watchdog, lifecycle and price multiple — with the five most commonly overlooked differences highlighted.
2. By user: individual/hobbyist, professional/studio, enterprise and industrial/edge. Each gets three recommended builds (GPU, CPU, memory, storage, PSU, cooling, indicative price and what it actually runs) plus its own pitfalls.
Also included: a VRAM cheat sheet (7 model-size tiers × FP16/INT8/INT4 × commercial and professional options), eight key metrics, budget splits for four segments, seven common mistakes and a 12-point pre-purchase checklist.
Engineering: hardware data lives in separate hardware.zh.js / hardware.en.js files because hardware needs its own update cadence. Every entry is indexed in site-wide search, and the homepage links straight to each segment.
The problem: the site only had list pages. Cards were visual containers with nowhere to go, so more than 400 items across news, models, glossary and the timeline could not be opened.
The fix: a unified detail panel. Items with an original link (auto-fetched news) make the whole card clickable and open the source; items without one open an in-site detail view with the full summary, specifications, tags and related entries, plus actions for official docs, a web search and copying a link.
Also completed: official documentation links for all 24 models; real websites for the two tools that had none; and the dead “button” that was a non-clickable span replaced with a working search link.
Found and fixed: freshly fetched news scored only 62–74, ranking below the curated demo data (74–98) — the English site showed no real news on its first page at all. Rebalancing the scoring rubric puts new items back near the top.
New tool: scripts/audit-links.js audits every page for dead links and unclickable cards. It now covers 18 pages and 420 items with zero issues.
1. RSS auto-update: new scripts/fetch_news.py and scripts/feeds.json fetch 10 sources, clean, deduplicate, classify and tag them, then emit assets/js/news-feed.js and label the items “Auto”.
2. Model comparison: select up to 4 models, get an attribute table with the best value highlighted, and copy it as Markdown. Selection is stored locally.
3. Six accent themes: Indigo, Ocean, Emerald, Violet, Sunset and Graphite, combinable with light and dark independently.
4. Bilingual architecture: UI strings moved to i18n.js, content split into data.zh.js and data.en.js, and this English site generated by scripts/build-en.js.
5. Scheduled deployment: .github/workflows/ adds a daily fetch job plus a Pages deployment job, and scripts/build-sitemap.js generates a bilingual sitemap and robots.txt. Push to GitHub and it runs unattended.
6. Fixes: sort handlers lost after re-rendering the comparison table; accordion double-binding; theme and filter breakage when localStorage or the history API is unavailable.
Nine sections: home, news hub, model library, tool directory, papers, learning path, glossary, timeline and about. Site-wide search (⌘K), dark mode, responsive layout, card and table views, category filters and pagination.
More languages (Japanese, Korean); charts for model leaderboards; saved bookmarks and reading history; keyword subscriptions and email digests; Markdown and PDF export.
